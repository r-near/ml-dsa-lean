# Cryptol differential, results of 2026-11-13

**Scope.** A differential on 7,106 compared cases (see the table), not an equivalence proof. `lean/Spec` and Galois's Cryptol
specification of FIPS 204 gave the same output on 7,100 of them, differed on 6 in a way explained by a documented deviation
of `lean/Spec` (NIST's erratum to Algorithm 3), and differed on none otherwise. This says that two independent transcriptions of the
standard agree on those inputs; the Cryptol specification is itself unverified, so agreement is evidence about both, not a proof about either. It says nothing about inputs that were not run, and the harness could not test the cases listed
under "Not covered".

Our side also ran 90 `SGA` lines (attempt counts of Algorithm 7's loop) and 36 `SGF` lines (forged boundary signatures, below); they
have no Cryptol counterpart and are not in the total. Over the 90 signing cases the loop took 1 to 20 attempts (mean 4.71), and 70 of
them needed at least two attempts, so the rejection paths and a non-zero κ were exercised, not only the first iteration.

`Verify` cases per set include: the valid signatures (`true`); mutations of the message, the context, c̃, z (random bits and single
coefficients set to ±(γ₁−β−1), ±(γ₁−β), ±(γ₁−β+1), γ₁), the hint (flipped byte, flipped count, five non-canonical re-encodings of
the same hint, exactly ω ones, empty); the public key; a signature under another key; and, from the forged boundary signatures,
signatures with ‖z‖∞ equal to γ₁−β−1 (valid, both sides accept), γ₁−β and γ₁−β+1 (hash-consistent, both sides must reject at step 13).

## Mismatches

None.

## Documented deviations (6)

All six are the same: **Algorithm 3 with a context of more than 255 bytes** (one per parameter set from the mutation family
`ver`, and one per set from `verx`).

- Minimal input: any public key, signature and message with a 256-byte context, for example an empty message and a 256-byte context
  (the `verx` lines).
- `lean/Spec`: `Verify` returns `some false`. Cryptol: `None`.
- Classification: **documented deviation**. FIPS 204 as published returns `⊥` from Algorithm 3 step 1, a value that does not fit the
  algorithm's Boolean result; NIST's erratum to FIPS 204 makes step 2 return `false`. `lean/Spec` follows the erratum; the Cryptol
  specification has the original pseudocode. Algorithm 2 (`Sign`) with a 256-byte context returns `none`/`None` on both sides and is
  compared as a match (the `sgn` lines include it).

Neither side is wrong. `compare.py` lists these in `mismatches.txt` as `DEVIATION(erratum-alg3)` so that they are never silently
accepted.

## Sensitivity: injected bugs

Each edit is applied by `inject.py` to a scratch copy of `lean/` (never to the committed `lean/Spec`), `spec-diff-cryptol` is rebuilt
(each injected executable differs from the pristine one), and the same vectors are run and compared with the saved Cryptol outputs.
The count is the number of `MISMATCH` lines of `compare.py` for that build; the 6 erratum deviations of the pristine run are
classified the same way in every injected run and are not counted.

| Injection (one edit in a scratch copy) | Detected | Mismatching lines | Where it shows |
|---|---|---:|---|
| `UseHint` step 3 tests `r₀ ≥ 0` instead of `r₀ > 0` | yes | 3 | `uh` (1 per set) |
| `RejBoundedPoly`/`CoeffFromHalfByte` accepts 9 for η = 4 | yes | 343 | `rbp65` 302, `exs65` 21, `kg_65` 10, `kgo_65` 6, `kgt_65` 4 |
| c̃ = H(w1Encode ‖ μ) instead of H(μ ‖ w1Encode) | yes | 141 | `sgn` 30 per set, `ver` 16 per set, `sgi` 1 per set |
| `HintBitUnpack` without the strictly-increasing check | yes | 381 | `hbu` 117/109/106, `ver` 17/16/16 (sets 44/65/87) |
| `HintBitUnpack` without the zero-padding check | yes | 287 | `hbu` 80/80/76, `ver` 18/17/16 |
| `Verify_internal` step 13 tests `‖z‖∞ ≤ γ₁−β` instead of `<` | yes | 12 | `ver` (4 per set) |
| Algorithms 2 and 3 refuse 255-byte contexts (`≥ 255` instead of `> 255`) | yes | 24 | `sgn` 6 per set (18, Algorithm 2), `ver` 2 per set (6, Algorithm 3) |

Seven of seven detected. Two notes: the `UseHint` bug flips three lines in total (one per set), so the `UseHint` edge-value cases
are what catches it, not the random ones; and the `‖z‖∞` bug is seen only through the forged boundary signatures (`ver` cases built from
`signLoop`), because bit flips of a valid signature fail the commitment hash first. Without those cases, that injection would have
passed.

**Correction to the first version of this file (the 255-byte-context row).** It said 6 mismatching lines, all `Verify`. That was
wrong; the right figure is 24. The vectors have 6 `Sign` cases per parameter set with a 255-byte context (`sgn_*`, 31 lines per set: at
`DIFF_SCALE=2` the generator signs five messages under each of six keys, one of the five with a 255-byte context, plus one 256-byte
context), and
the injected build returns `none` on all 18 of them where Cryptol returns a signature; the 6 `Verify` cases (2 per set) are the other
part. The mutation was never weaker than described. The summary of the first run was wrong because the comparator that produced it on
the build box classified a `none` from our side against a signature from Cryptol as a deviation (its saved `mismatches.txt` lists 18
`DEVIATION(fuel)` lines for `sgn_*`), a class that the committed `compare.py` does not have: it reports such a line as a mismatch,
by design (see its header), and the injection summary counts `MISMATCH` lines. The pristine run was unaffected (its `sgn` lines all
match, and no line of it was classified as anything but a match or the erratum deviation). This run uses the committed
`compare.py` and the output is above.

## Not covered

- Keys and signatures of the wrong length: the Cryptol types fix the lengths, so a wrong length is a type error and cannot be run.
  `lean/Spec` returns `false` for these (Algorithm 3's length check); that branch is not exercised here.
- Messages that are not whole bytes (FIPS 204 allows them; `lean/Spec` has byte-string messages).
- HashML-DSA and external μ: not in either specification.
- Exhaustion of the fuel of a rejection loop on our side, and Algorithm 7's κ + ℓ > 2^16 refusal: not reachable by these cases.
  A `none` from our side against a value from Cryptol would be reported as a mismatch; there were none.
- Randomness beyond the seeds in the vector files: the case counts above are all there is. A larger `DIFF_SCALE` or another `DIFF_SEED`
  runs more.
- Cryptol 3.6.0 against the 3.2.0 the Cryptol specification's README names. The specification loads and evaluates unchanged; the
  key generation and deterministic signing agreeing with `lean/Spec` (which agrees with ACVP) shows the newer interpreter is not
  producing different values for this specification.
