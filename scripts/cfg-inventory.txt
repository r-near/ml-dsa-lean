# The cfg inventory of src/ (scripts/cfg_inventory.py checks this file against the source; read the header there).
#
# Every entry is a place where the compiled text depends on the build configuration. The conditions are of four kinds:
#
#   avx2 dispatch   `feature = "avx2"` with `target_arch = "x86_64"` and `miri` (the extraction sets `--cfg miri` and the feature):
#                   which of two definitions a build gets. Verify has none (round 12: it always calls the 4-way code and the
#                   target features of the build decide what LLVM emits; scripts/check-feature-independence.sh compares the
#                   extractions under two sets of target features and its whitelist is empty). The NTT dispatch (src/ntt.rs,
#                   src/cpu.rs) is the one that remains for Sign and KeyGen: its AVX2-build body is a plain `if has_avx2()` over
#                   two compilations of the same proved body, and the extraction sees the portable body.
#   miri            `cfg(miri)` selects the identity where the compiled build has `core::hint::black_box` (the identity on values),
#                   so that the extraction sees plain code. Documented in docs/assurance.md (CT-1, CT-2).
#   zeroize         `feature = "zeroize"`: wipes of secrets in Sign and KeyGen (and the secret-key decoders), outside the Lean
#                   model by design (docs/limitations.md). None of them is on a verify path (verify handles only public data).
#   internals       `feature = "internals"` / `cfg(test)`: visibility and test hooks; the module text is the same.
#
# Besides cfg attributes and `cfg!`, the scan also lists every other construct that reads a compile-time source: `cfg_if!`, `cfg_match!`,
# `env!`, `option_env!`, `include!`, `include_bytes!`, `include_str!`, `is_*_feature_detected!`, a plain `#[path = ..]`, a
# `macro_rules!` whose body mentions cfg, any stray `cfg` identifier (form `cfg-token`), and a build script (`build.rs` or a
# `build =` key). src/ has none of these today but the `cfg!` in src/cpu.rs and the two `#[path]` attributes below.
# (scripts/extract_hash.py also rejects a build script and an `env!`/`include!`-style macro in src/ outright, whatever is listed here.)
#
# A new or changed entry means a configuration-dependent computation was added or moved: review it against these four kinds.
# Regenerate a skeleton with `python3 -I scripts/cfg_inventory.py --init` and write the justification by hand.
