# ML-DSA verify, round 9: an aligned scratch replaces `align_frame()`, 2026-11-09

Branch `fv-p9` (from `fv-p8`, 40ee0de). The performance-relevant change of this round: `align_frame()` (a `black_box` anchor,
empty under `--cfg miri`) is gone from `src/`. `verify_core` now owns a `#[repr(align(32))]` `VerifyScratch` (the w'1 polynomials
and their byte encoding) and computes in it, so the three `#[target_feature(enable = "avx2")]` wrappers, in particular
`verify_prepared_avx2`, which only borrows its key, realign their stack frames because of data the proved code really uses.
Nothing else in `src/` changed behavior (comments aside). Speed is the prerequisite for the proof work; this file is the evidence.

Built and run as in [2026-11-08-p8](2026-11-08-p8.md): nearcore profile and target features (no AVX2 in the baseline), one
pinned core of an AMD EPYC 9B14 (Zen 4, KVM guest) at a measured 3.40 GHz, rustc 1.99.1, ASLR off, load about 1.0
(`uptime` at the end of each padding: 1.00 to 1.17). Padding is the environment padding in bytes (0, 672, 2752). Binaries:
`p9-fv40` is fv-p8 (40ee0de), `p9-fastverify` is `fast-verify` (3b79427), rebuilt from their commits.
