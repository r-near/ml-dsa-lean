# ML-DSA verify, round 10: one `_with` text in every build, 2026-11-09

Branch `fv-p10` (from `fv-p9`, 8035f65). Round 10 changes how the AVX2 dispatch is written, not what it computes: the `_with`
functions of `src/fast_verify.rs` are one text in every build, `cpu::Avx2` is an uninhabited enum where the dispatch does not exist,
and the three `unsafe` calls moved to `src/fast_verify/dispatch.rs` (`docs/assurance-history.md`, "Round 10"). The verify wrappers are the same
three `#[target_feature(enable = "avx2")]` functions. This file is the evidence that the compiled fast path did not move.

Built and run as in [2026-11-09-p9](2026-11-09-p9.md): nearcore profile and target features (no AVX2 in the baseline), one pinned
core of the build box's Zen 4 CPU, rustc 1.99.1, ASLR off, paddings 0, 672 and 2752 bytes of environment, `bench/ab.sh`. Binaries:
`p10ab-fv9` is fv-p9 (8035f65), `p10ab-fv10` is the `src/` of this branch (identical to the final tree: the commits after the last
`src/` change touch scripts, documentation and `checkct/` only). Load: 4.2 to 4.6 at the start of each padding, from the BINSEC smoke
containers running at the same time (not an idle box). The two binaries ran interleaved, so that load hits both alike.

## Object code

`scripts/check-avx2-inlining.sh`: `OK: 4-way permutation vectorized in every wrapper; verify-only arithmetic fully inlined;
verify wrappers realign their frames; 57462 lines of ymm code` (p9: 57462). The script now inspects the assembly of the build it
just ran, at its own path. It is a performance check (the AVX2 body is compiled with AVX2, inlined and vectorized, and the frames
are realigned), not a correctness or constant-time check; verify handles public data only.

Sign and KeyGen: `checkct/compare-code.sh` builds the checkct driver of fv-p9 (8035f65) and of this branch in the default release
profile (nightly-2026-10-06) for riscv32imac, thumbv7em and x86_64, each without and with the driver's `avx2` feature, and compares
every function after masking addresses, address-like immediates, symbol operands and the symbol hashes (`llvm-objdump -d`): 234, 239,
234, 234, 239 and 235 functions respectively, every one identical, none added or removed (the comparison is sensitive: the
x86_64 binaries without and with `avx2` of one tree differ in 104 functions). This is a comparison of instruction streams, not a
BINSEC verdict; the BINSEC results of this round are in `docs/assurance-history.md` section 4 and `checkct/results/smoke-fast-verify/`.
The profiles with nearcore's flags are not covered by this comparison.
